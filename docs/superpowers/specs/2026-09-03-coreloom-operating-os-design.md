# Coreloom 운영 OS 설계

## 1. 결정 요약

Coreloom은 1인 개인사업자가 강의·앱·온라인 서비스를 동시에 운영하기 위한 비공개 회사 운영 OS다.

- **운영 정본:** 고객사, 견적·계약·청구, 프로젝트, 매출, 회사 설립 준비, 대표 승인
- **기록 수집 정본:** Recho의 메일·통화·회의·Google Calendar 기록
- **사람의 권한:** 대표만 금전 확정, 외부 발송, 계약 체결, 권한 변경, 외부 공개를 실행
- **AI의 권한:** 근거를 바탕으로 현재 합의·다음 할 일·위험을 제안하고, 초안을 만든다. 최종 확정은 하지 않는다.

## 2. 목표와 비목표

### 목표

1. 개인사업자 설립과 운영 준비가 증빙과 함께 끝났는지 확인한다.
2. 고객사 프로젝트를 견적부터 분할 입금까지 한 흐름으로 관리한다.
3. 이메일·통화·회의의 시간 맥락을 잃지 않고 의사결정 근거로 연결한다.
4. 앱·구독 서비스 매출을 고객사 프로젝트 매출과 같은 원장에서 본다.
5. 운영 매뉴얼과 변경 이력을 관리자 전용 화면에서 읽는다.

### 비목표

- 급여, 4대보험, 원천세, 재고, 구매·물류를 자체 구현하지 않는다.
- AI가 사람 승인 없이 돈을 보내거나, 계약·세금계산서·이메일을 확정 발행하지 않는다.
- Recho의 원문 저장소를 Coreloom으로 통째로 복제하지 않는다.

## 3. 시스템 경계

| 영역 | Coreloom의 책임 | 외부 정본 |
| --- | --- | --- |
| 회사 설립 | 체크리스트, 증빙 링크, 완료 확인 | 관공서·은행·세무 서비스 |
| 고객사와 프로젝트 | 고객, 담당자, 견적, 계약, 업무, 진행률, 청구 일정 | 없음 |
| 기록 맥락 | 고객·프로젝트에 연결할 기록과 대표 확정 결정 | Recho 원문과 원본 제공자 |
| 세금계산서 | 발행 요청·상태·승인번호·이력 관리 | 팝빌과 국세청 전송 결과 |
| 계약 | 계약 초안·버전·체결 상태·보관 | 전자서명 사업자 또는 날인 원본 |
| 문서 | 비공개 문서 메타데이터·권한·연결 | 암호화된 파일 저장소 |

Recho 연결은 읽기 중심이다. Coreloom은 원문 URL 또는 원본 식별자, 발생 시각, 연결한 사람, 연결 이유를 보관한다. 원문을 수정하거나 문맥 없는 요약만 정본으로 삼지 않는다.

## 4. 데이터 모델

- **사업:** 강의, 파인디 앱, ALT. LIFE처럼 독립된 수익·비용 흐름
- **고객사와 담당자:** 사업자 정보, 연락처, 관계 상태, Recho 기록 연결
- **기회와 프로젝트:** 수주 단계, 계약 금액, 일정, 진행률, 담당 에이전트
- **견적서:** 항목·수량·단가·세금·할인·납기·비고·버전·PDF 발송 이력
- **계약:** 견적 연결, 계약 버전, 전자서명 또는 날인, 최종 원본, 체결일
- **청구 일정:** 착수금·중도금·잔금 또는 구독 반복 청구, 청구일·입금 예정일·입금 확인일
- **세금계산서:** 발행 요청, 외부 발행 식별자, 승인번호, 전송·수신 상태, 수정 발행 연결
- **업무와 일정:** 사업·프로젝트·고객사 연결, 담당자 또는 AI 에이전트, 기한, 완료 조건
- **근거 기록:** Recho 원문 연결, 시간순 타임라인, AI 제안, 대표 확정 또는 반려
- **문서:** 파일 원본, 접근 권한, 연결 대상, 업로드자, 버전, 보존 상태

## 5. 대표 업무 흐름

### 5.1 개인사업자 준비

대표는 설립 준비함에서 사업자 등록, 사업용 계좌, 발행용 인증 수단, 세무 설정, 기본 계약·견적 양식의 완료 여부를 확인한다. 각 항목은 완료 체크만으로 끝나지 않고 증빙 파일 또는 확인 링크가 있어야 완료된다.

### 5.2 고객사 프로젝트 수주와 납품

1. 고객사와 담당자를 등록하고 Recho 기록을 연결한다.
2. 견적서를 여러 버전으로 작성한다. 발송한 버전은 PDF와 이메일 발송 이력으로 보존한다.
3. 견적을 계약으로 전환한다. 전자서명 완료본 또는 날인한 스캔 원본을 최종 계약본으로 표시한다.
4. 프로젝트에 업무·일정·진행률·분할 청구를 등록한다.
5. Recho 기록을 시간순 타임라인에서 확인한다. AI의 합의·다음 할 일·위험 제안은 근거 링크와 함께 표시한다.
6. 대표가 제안을 확정하거나 반려한다.
7. 청구서를 PDF·이메일로 보낸 뒤 세금계산서를 발행하고 입금을 확인한다.
8. 종료 후 계약·산출물·정산·결정 이력을 비공개 문서함에 보관한다.

### 5.3 앱·구독 서비스

앱·구독 서비스는 사업으로 등록한다. 반복 청구, 환불, 수수료, 정산일을 고객사 프로젝트와 같은 매출 원장에 기록한다. 결제대행사의 자동 수집은 결제 채널이 확정된 뒤에만 연결한다.

## 6. 화면 구조

### 대표 대시보드

- 최상단: 승인 대기·오늘 업무·연체 입금·미분류·현금 리듬
- 오늘 할 일 한 목록과 이번 달 입금·지급 추이
- 중간: 진행 중 고객사 프로젝트의 견적·계약·청구 단계와 다음 할 일
- 하단: 이번 주 일정, 최근 결정. 설립이 끝나지 않았으면 진행률

### 고객사 프로젝트 화면

- 본문: 단계별 진행률, 업무, 견적·계약·청구, 문서
- 오른쪽 레일: Recho 메일·통화·회의의 시간순 근거, 원문 열기, AI 제안, 대표 확정 상태
- 동일 화면에서 기록의 최신 발언과 전후 맥락을 확인한다.

## 7. 외부 연동과 활성화 조건

### Recho

Recho의 메일 조회·분류, Calendar 조회·생성·수정, 회의록·통화 흡수 기능을 Coreloom의 수집 연결점으로 사용한다. Coreloom은 기록을 고객사·프로젝트의 공식 근거로 연결할 때만 자체 메타데이터를 만든다.

### 팝빌 전자세금계산서

팝빌 어댑터는 발행 요청, 상태 조회, 발행 결과 웹훅, 수정 발행 연결을 제공한다. 실제 발행 기능은 개인사업자 등록, 발행용 인증 수단, 팝빌 API 계약과 운영 자격 증명이 준비된 뒤 활성화한다. 발행 요청은 중복 실행을 막는 고유 키를 사용하고, 실패·대기·완료 상태를 구분한다.

### 계약과 이메일

계약은 전자서명 서비스 연동 또는 날인 원본 업로드를 모두 지원한다. 전자서명 공급자는 선정 전까지 연결하지 않는다. 견적서·청구서 이메일은 대표가 발송 내용을 확인하고 승인한 뒤에만 보낸다.

## 8. 안전장치와 실패 처리

- 최종 견적서, 체결 계약서, 발행된 세금계산서는 덮어쓰지 않는다. 수정본은 새 버전 또는 수정 발행으로 남긴다.
- 외부 발송과 발행은 요청·승인·전송 결과·외부 식별자를 모두 남긴다.
- 전송 결과를 받지 못하면 `완료`로 표시하지 않고 `확인 필요`로 남긴다.
- AI 제안에는 출처 기록과 생성 시각을 붙인다. 근거가 없으면 확정 후보로 올리지 않는다.
- 개인·고객사·재무 자료는 대표 전용 기본값이며, 외부 협업자가 생기면 최소 권한으로 별도 부여한다.

## 9. 출시 순서와 검증

### 첫 구현

1. 회사 설립 준비함과 비공개 문서 보관함
2. 고객사·견적서 버전·PDF·이메일 발송 승인
3. 날인 계약 보관, 프로젝트·업무·캘린더·진행률·분할 청구
4. Recho 타임라인 연결, AI 제안, 대표 확정 이력
5. 매출 원장과 입금 상태

### 외부 자격 준비 후 활성화

1. 팝빌 실발행과 결과 웹훅
2. 전자서명 공급자 연동
3. 앱·구독 결제 채널 자동 수집

### 완료 검증

- 설립 준비 항목은 증빙 없이 완료 처리할 수 없어야 한다.
- 고객사 견적서 수정본이 이전 PDF와 발송 이력을 바꾸지 않아야 한다.
- 날인 계약 원본과 전자서명 계약이 같은 계약 상태 흐름으로 조회돼야 한다.
- Recho 기록의 AI 제안은 원문과 시간순 맥락을 열 수 있어야 하며, 대표 확정 전에는 공식 결정으로 보이지 않아야 한다.
- 분할 청구·세금계산서·입금은 각자 상태와 외부 식별자로 추적돼야 한다.
- 권한 없는 계정과 AI 에이전트는 외부 발송·발행·확정을 실행할 수 없어야 한다.

## 10. 승인된 화면 결정

- 대표 대시보드: 설립 준비 우선
- 고객사 프로젝트: 대화 맥락을 오른쪽 레일에 상시 표시
- 제품 구조: Coreloom 중심 연결형

> 적용 기준 — 운영 도구 화면은 명시 라벨과 표준 위치를 사용하며, AI 제안·근거·대표 확정 상태를 시각적으로 분리한다. 실제 UI 값은 구현 전에 Coreloom 전용 디자인 토큰으로 정한다.
