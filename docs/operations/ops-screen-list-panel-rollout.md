# 운영 화면 리스트·작성 패널 롤아웃과 필드 격차

> 고객사(`/clients`)에서 쓴 방식(리스트 먼저 · 헤더 `+` · 구역·2열 작성 패널 · 실무에 필요한 필드)을 다른 운영 화면에 같은 **껍데기**로 맞추기 위한 정본이다.
> UX 껍데기는 견적·에이전트·고객사에서 검증된 것을 가져오고, **필드 세트는 면마다 역할로 다시 고른다.**

상태 기준:
- **완료**: 리스트+패널 + 추천 필드가 `main`에 있음
- **다음**: 바로 구현할 순서
- **보류**: MVP 밖이거나 자격·공급자 대기

---

## 공통 UX (이미 정한 것)

| 항목 | 선택 |
|---|---|
| 첫 화면 | 리스트 |
| 생성 | 헤더 `+` → `CreatePanel` (`?new=1`) |
| 폼 레이아웃 | 구역 라벨 + 짧은 칸 2열 · 긴 칸 한 줄 (견적 `quote-form`) |
| 스크롤바 | 작성 패널 얇은 pill, `--line`/`--muted` 톤 |
| 가져오지 않음 | 견적 INVOICE·원가 xlarge 레이아웃 |

## 1. 고객사 `/clients` — 완료, 남은 후보

**지금:** 상호·사업자번호·대표·업태·종목·주소·전화·이메일·홈페이지·사업자등록증 위치, 담당자·계산서 수신.

**외부 사례에서 더 두는 것**

| 후보 | 출처·이유 | Coreloom |
|---|---|---|
| 과세 유형(일반/간이/면세) | 세무·발행 판단 | **다음 후보** |
| 고객 은행·계좌·예금주 | 환불·매입 지급 시. 매출만이면 우리 계좌(`/company-setup`)만 | **선택·이후** |
| 통장사본 위치 | 계좌와 세트 | 계좌와 같이 |
| 거래 유형(매출/매입/동시) | ERP 거래처 마스터 | 이후(매입 거래처 통합 시) |
| 담당자 부서·직함 분리 | 그룹웨어 거래처 | 역할 칸으로 충분하면 보류 |
| 사업자등록증 파일 업로드 | 문서함 연동 | 지금은 위치/링크, 업로드는 문서함과 묶을 때 |

## 2. 프로젝트 `/clients-projects`

**지금:** 고객사·이름·상태·진행률. 상단 인라인 폼.

**외부(서비스업 ERP: 제안→견적→계약→프로젝트→청구)**  
범위 설명, 시작·목표 종료일, 견적/계약 연결, 내부 담당(PM), 예산·청구 방식, 투입 시간.

| 추천(이번에) | 이유 |
|---|---|
| 고객사·이름·상태·진행률 | 기존 |
| 요약(범위 한 줄) | 견적·업무와 맞추는 맥락 |
| 시작일·목표 종료일 | 일정·대시보드 |
| 리스트+`+` 패널 | UX 통일 |

| 이후 | 이유 |
|---|---|
| 내부 담당(대표/에이전트) | 배정은 업무에 이미 있음 |
| 예산 한도 | 견적 합계로 대체 가능 |
| 견적·계약 FK 강제 | 이미 화면에서 연결 |

## 구현 순서 (추천)

1. **프로젝트** — **완료**(리스트+`+`, 요약·일정 0024)
2. 업무 · 근거 · 제안 · 문서함 — **완료**(패널 UX, 필드 유지)
3. 계약 · 청구 — **다음**(폼이 둘이라 패널 설계가 한 단계 큼)
4. 매출 · 비용 — **다음**
5. 설립 준비는 레이아웃 정리만
6. 에이전트는 톤만 맞춤(이미 리스트+`+`)

**대안 순서:** 필드 추가 없이 전 화면 패널 UX만 먼저 깔고, 필드는 두 번째 패스.
