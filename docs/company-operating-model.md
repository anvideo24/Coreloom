# Coreloom 회사 운영 모델

## 회사의 형태

Coreloom의 첫 사용자는 **1인 창업자와 AI 에이전트 팀**이다. 한 회사 안에서 다음처럼 성격이 다른 사업을 동시에 운영한다.

- 강의·교육 콘텐츠
- 앱과 디지털 도구
- ALT. LIFE 같은 온라인 서비스
- 이후 생기는 신규 실험과 제품

따라서 ERP는 단일 프로젝트 관리 도구가 아니라, 여러 사업의 사람·일·돈·결정을 분리해서 보고 필요한 곳에서 연결하는 운영 본부가 되어야 한다.

## 운영 단위

| 단위 | 의미 | 예시 |
| --- | --- | --- |
| 회사 | 법인 또는 개인사업자의 전체 운영 주체 | Coreloom 운영 회사 |
| 사업 | 독립된 수익·비용 흐름을 가진 제품 또는 서비스 | 강의, 파인디 앱, ALT. LIFE |
| 프로젝트 | 사업 안의 기한 있는 실행 단위 | 신규 강의 개설, 앱 기능 출시 |
| 업무 | 담당자와 마감일을 가진 실행 항목 | 커리큘럼 초안, 화면 설계 |

모든 매출·비용·계약·업무는 최소한 하나의 사업 또는 프로젝트와 연결한다. 연결할 수 없으면 `미분류`로 남겨 대표가 분류한다.

## 역할과 책임

| 역할 | 주체 | 할 수 있는 일 |
| --- | --- | --- |
| 대표 | 사람 1명 | 모든 데이터 조회, 최종 승인, 자금·권한·외부 공개 결정 |
| AI 에이전트 | 시스템 계정 | 정해진 범위의 자료 조사, 초안 작성, 업무 업데이트, 승인 요청 초안 |
| 외부 협업자 | 필요 시 사람 계정 | 맡은 프로젝트의 제한된 업무·자료 처리 |

AI 에이전트는 직원처럼 업무를 돕지만 법적·금전적 최종 권한을 갖지 않는다. 모든 행동은 어느 에이전트가 어떤 지시와 권한으로 수행했는지 남겨야 한다.

## 초기 승인 기준

초기 1인 운영에서는 금액 구간을 나누지 않는다.

- 모든 지출 확정, 계약 체결, 매출 확정, 환불, 계정·권한 변경, 외부 공개는 대표가 직접 승인한다.
- AI 에이전트는 제안·초안·요청 등록까지만 할 수 있다.
- 자동 결제·자동 이체·자동 외부 발행은 대표가 건별로 허용하기 전에는 실행하지 않는다.
- 인원이 늘면 금액 구간과 승인 단계를 별도 규칙으로 추가한다.

## MVP에 필요한 추가 정보

1. 사업별 손익: 강의·앱·온라인 서비스의 매출·비용을 각각 본다.
2. AI 에이전트 등록부: 이름, 목적, 허용 업무, 접근 범위, 상태를 관리한다.
3. 에이전트 작업 이력: 요청자, 실행 에이전트, 입력 자료, 결과물, 사람 승인 여부를 남긴다.
4. 대표 승인함: 지출·매출·입금 확정, 계약 체결, AI 제안, 에이전트 요청을 `/approvals`에서 한곳으로 확인한다. 메일 발송처럼 보낼 때 승인하는 일은 목록에 두지 않는다.

## 아직 사람의 판단이 필요한 것

- 법인 설립 시점과 사업자 형태
- 매출 채널: 강의 플랫폼, 앱스토어, 직접 결제 등
- 실제 금전 거래에 연결할 은행·카드·회계 서비스
- AI 에이전트별 접근 가능한 고객·계약·재무 데이터 범위
