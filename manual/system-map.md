# 시스템 구조도

회사 기록과 자료의 관계를 설명하는 정본이다. 업무 순서는 [업무 지도](work-map.md), 목표·확인 상태는 [시스템 진행 현황](system-progress.md)에서 본다. 연결선은 관계이며 자동 처리·전체 정보 전송·실시간 정상 연결을 뜻하지 않는다.

아래 표의 다섯 구성과 설명을 관리자 화면이 읽는다. 실제 고객명·금액·계정·서버 주소를 넣지 않는다.

| ID | 구성 | 요점 | 상세 제목 | 관계 | 설명 1 | 설명 2 | 설명 3 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| records | 회사 기록 | DB에 저장 | 회사 기록과 파일 원본은 다릅니다 | 운영 화면 ↔ 권한 검사 ↔ Neon 데이터베이스 | 고객·프로젝트·견적·청구 등 구조화된 회사 기록을 보관합니다. | 문서의 정보와 파일 식별자를 기록하지만, 업로드한 파일 원본은 서버 PC에 별도 보관합니다. | 이 도식에는 실제 고객명·금액·계정·접속 주소를 표시하지 않습니다. |
| files | 원본 파일 | 서버 PC 보관 | 원본은 서버 PC에 보관합니다 | 문서함·대화 첨부 ↔ 비공개 파일 보관 | 문서 원본과 대화 이미지는 서버 PC의 비공개 영역에 저장합니다. 휴대폰 자체 저장소가 아닙니다. | 대표가 원본을 받는 것과 AI가 원본을 읽는 것은 별개입니다. 문서함 원본 전체 해석 권한을 뜻하지 않습니다. | 서버 PC를 옮기면 파일 이관도 필요합니다. DB만 옮긴다고 원본까지 따라가지 않습니다. |
| ai | AI 대화 | 허용 자료 조회 | AI는 허용한 자료만 읽습니다 | 자료 조회 권한 확인 → 구독 모델 → 답변 | 고객사·프로젝트·견적·업무·문서 목록과 지정한 PC 폴더 중 허용한 자료만 조회합니다. | 구독 실행기는 서버 PC에서 동작합니다. 접속한 휴대폰의 폴더를 읽는 기능은 아닙니다. | 현재 대화 도구는 읽기 전용입니다. 회사 기록 변경·외부 발송·금액 확정을 대신하지 않습니다. |
| external | 외부 연결 | 연결별 조건 | 외부 연결마다 조건이 다릅니다 | 로그인 · 메일 발송 · 근거 연결 | Neon Auth: 로그인과 대표 허용 검사를 거쳐 운영 화면에 접근합니다. | Resend: 발송 설정과 대표 승인이 있어야 메일을 보냅니다. 요청 접수와 수신 완료는 다릅니다. | Recho: 원문 식별자·시각·링크를 수동 연결합니다. 자동 동기화는 미제공입니다. 세금계산서·은행 자동 연동도 연결된 것으로 표시하지 않습니다. |
| manual | 운영 문서 | Git 원본 표시 | 화면은 문서 원본을 읽습니다 | 제품 매뉴얼 + 공용 작업 규칙 → 관리자 화면 | Coreloom의 설명과 규칙은 제품 저장소에서, 공용 작업 방식은 working-method 저장소에서 읽습니다. | 화면용 사본을 별도 정본으로 만들지 않습니다. 내용 변경은 문서 원본과 검증을 함께 갱신합니다. | 실시간 감시판이 아닙니다. 문서 정보를 펼쳐 원본 커밋을 확인하고, 시스템 진행 현황에서 검증 근거를 봅니다. |
