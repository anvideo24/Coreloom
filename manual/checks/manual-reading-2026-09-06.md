# 매뉴얼 읽기 화면 확인

## 범위와 상태

원본 문서의 차례·글자 위계·문서 정보 접기·표 내부 스크롤을 개선했다. 홈 분류, 문서 원문, 검증 판정, 권한과 DB는 바꾸지 않았다. 시스템 지도·문서 검색·모바일 표 카드 변환은 포함하지 않는다.

마지막 코드 검토에서 목차에도 본문과 같은 한글 단어 단위 줄바꿈을 적용했다. 공백 없는 긴 토큰만 강제로 줄을 바꾼다. 이 최종 줄바꿈 보완은 아래 화면 측정 이후이며 별도 실기기 재확인은 하지 않았다.

구현과 PC 부분 검증을 마쳤다. main 포함 여부는 [PR #107의 병합 상태](https://github.com/anvideo24/Coreloom/pull/107)에서 확인한다. 아래 개발 중 화면 측정은 상시 실행 환경 반영 증거가 아니다.

## 실제 화면 확인

Windows PC의 로그인된 IAB에서 공용 일하는 방식과 시스템 진행 현황을 확인했다. 아래 크기는 요청한 에뮬레이션 크기가 아니라 DOM에서 읽은 CSS 픽셀이다. 실물 Fold 시험은 아니다. 확인 후 브라우저 크기 설정을 초기화했다.

| 항목 | 실측 | 판정 |
| --- | --- | --- |
| 원본 문서 342×798 | 페이지 가로 넘침 0px, 차례·문서 정보 기본 닫힘 | 확인 |
| 원본 문서 724×804 | 가로 넘침 0px, 1열 본문 약616px | 확인 |
| 원본 문서 1440×1000 | 가로 넘침 0px, 차례 약240px + 본문 약672px | 확인 |
| 원본 문서 3151×2160 | 가로 넘침 0px, 본문 약672px 유지 | 확인 |
| 모바일 차례 | 펼친 링크 8개 모두 약48px 높이 | 확인 |
| 차례 이동 | ‘6. 보고할 때’ 선택 후 해당 제목이 화면 안에 표시 | 확인 |
| 글자 위계 | 문서 h2 24px, h3 20px | 확인 |
| 진행 현황 1440px | 기존 콘텐츠 폭 약1108px 유지, 가로 넘침 0px | 확인 |
| 진행 현황 342px | 가로 넘침 0px, 표 영역251px 안에576px 표 스크롤 | 확인 |
| 3840px 원본 4K | 도구의 크기 제한으로 실제 폭이3151px로 측정됨 | 미검증 |
| 실제 Fold·브라우저200% 확대·사람 탐색 시간 | 이번에 측정하지 않음 | 미검증 |

화면 확인은 공유 개발 폴더에서 구현한 직후 진행했다. 이후 다른 동시 작업과 섞이지 않도록 소유 코드 3개 파일만 별도 작업 폴더로 이동했다. 따라서 이 기록은 개발 중 화면의 검증이며 현재 실행 중인 main 화면 반영 증거가 아니다.

## 자동 검사

- `apps/web/src/components/admin-manual-frame.test.tsx`: 제목 ID 충돌, 차례 링크, 본문·링크·표 보존, 접힌 정보, 차례 없는 레이아웃을 검사한다.
- 독립 작업 폴더에서 전체 63개 시험 파일·419개 시험 및 타입 검사가 통과했다. PR의 CI는 별도 확인한다. 기기 측정이나 F01–F07 검증 통과로 대체하지 않는다.
- 이후 CI에서 419개 단언은 통과했지만 매뉴얼 시험이 끝난 뒤 `window is not defined` 오류 5건으로 실패했다. 시험별 React 정리가 누락돼 다음 시험에 DOM이 남는 것을 실패 검사로 재현했다. 기존 시험과 동일하게 `afterEach(cleanup)`을 추가했으며 다음 시험 시작 시 DOM이 비어 있는지도 검사한다. 제품 코드나 판정 단언을 약화하지 않는다. 최종 CI 결과는 위 PR에서 확인한다.
