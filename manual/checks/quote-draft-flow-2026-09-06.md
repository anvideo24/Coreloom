# 고객사 → 견적 초안 실사용 검증

## 이번에 확인하는 것

견적을 작성하다 고객사를 새로 등록하고, 입력을 반복하지 않은 채 견적 초안을 저장할 수 있는지 확인한다. 닫기·새로고침·화면 전환 뒤의 초안도 비교한다. 실제 고객 정보·외부 발송·금액 확정은 사용하지 않는다.

환경은 개발 Windows PC의 Chrome 2560×1215다. Neon의 현재 브랜치·컴퓨트 정보와 로컬 연결 설정을 대조해 `ai-development`임을 확인했다. 실제 휴대폰 검증이나 사람의 작성 시간 측정이 아니다.

## 개선 전 — 실제 화면에서 발견한 실패

검증 코드: `b3d0587`.

| 동작 | 기대 | 실제 결과 |
| --- | --- | --- |
| 견적 입력 → 고객사 등록 화면 → 닫기 → 새 견적 | 제목·항목·단가·설명·메모 유지 | 제목·항목·단가 유지, 고객용 설명·메모 손실 |
| 인라인 고객사 상호 입력 → 닫기 → 새 견적 → 고객사 등록 | 입력한 상호 복원 | 빈 상호로 열림 |
| 인라인 고객사 저장 → 견적 복귀 | 새 고객사 자동 선택·이전 견적 유지 | 새 고객사는 선택 목록에 있으나 자동 선택되지 않음. 이전 견적 제목도 손실 |

마지막 실패에서는 잘못된 고객사로 저장하지 않도록 견적 저장을 멈췄다. 재검증까지 합쳐 개발 DB에 명확히 검증용으로 이름 붙인 가상 고객사 2건(A·B), B의 견적 초안 1건을 남겼다. 발송·계약 체결·매출 확정은 하지 않았다. 실제 고객 자료는 수정하지 않았다.

## 개선 후 체크리스트

검증 코드: `593174416eefd058bedbbce32e9c090e9c5fbc40`. 작업 가지에서 확인했으며 main 병합·CI 빌드 판정은 별도다.

| 검사 | 완료 기준 | 현재 결과 |
| --- | --- | --- |
| F01-01 | 같은 고객 정보 재입력 0회 | PC 한 사례 통과 · 고객명 재입력 0회. 담당자·프로젝트 없는 최소 사례 |
| F01-02 | 고객사 등록을 위한 외부 화면 왕복 0회·새 고객사 연결·견적 유지 | PC 한 사례 통과 · 외부 왕복 0회, 등록 직후 새 고객사 자동 선택·견적 입력 5/5 유지 |
| F01-04 | 저장·재조회한 고객사·품목·금액 일치 | PC 한 사례 통과 · 고객사·제목·품목·설명·메모·합계 6/6 일치. 저장 후 전체 새로고침으로 재확인 |
| F02-01 | 닫기·새로고침·다른 화면 복귀 후 초안 유지 | 부분 확인 · PC 견적 3/16조합, 각각 입력 5/5 보존. 인라인 상호 닫기·재열기도 별도 통과. 전체 통과 아님 |

### 무엇을 바꿨나

1. 제출용 숨은 값과 화면 입력이 분리된 견적 설명·메모를 복원 표식으로 저장한다.
2. 복원 이벤트가 일부만 복원된 상태를 다시 초안에 덮어쓰지 않게 한다. 닫기 후 재열기뿐 아니라 그 뒤 새로고침도 연속 확인했다.
3. 견적과 인라인 고객사 폼의 수명을 분리하고, 등록 후 URL로 지정된 새 고객사가 오래된 초안 선택보다 우선하도록 한다.

### 입력량과 화면 이동

| 항목 | 이번 사례 실측 |
| --- | --- |
| 직접 입력한 서로 다른 칸 | 6개 · 견적 주제, 작업명, 단가, 고객용 설명, 메모, 고객사 상호 |
| 한 번 작성하는 데 직접 입력한 글자 | 58자 · 공백 포함, 자동 천 단위 쉼표 제외 |
| 반복 고객명 입력 | 0회 |
| 고객사 등록을 위한 외부 화면 왕복 | 0회 |
| 정상 작성 경로의 내부 폼 전환 | 2회 · 견적→고객사 등록→견적 |
| 견적 목록에서 저장 상세까지 페이지 전환 | 1회 · 고객사 저장은 같은 견적 경로의 검색 인자만 바뀜 |
| 초안 내구성 확인용 추가 조작 | 닫기·재열기, 새로고침, 다른 페이지 왕복은 위 정상 경로 수와 분리 |
| 저장 후 새 견적에 이전 검증 입력이 되살아남 | 0개 |

거래 유형·발행일·유효기간·수량·역할은 기본값을 사용했다. 최소 필수 입력 수 전체를 주장하는 것이 아니라, 설명·메모 보존을 함께 검증한 이 사례에서 실제 입력한 수다.

### 자동 검사와 한계

- 설명·메모 복원을 추가한 회귀 시험이 수정 전 실패하고 수정 후 통과했다. 연속 재마운트 회귀도 포함했다.
- 관련 초안·수주 화면 시험 18개 통과, 전체 시험 470개(72개 파일)·타입 검사 통과.
- 변경 파일 lint는 기존 `set-state-in-effect` 3건 때문에 실패했다. 같은 파일의 수정 전 HEAD를 검사해 동일 3건임을 확인했다. 이번에 새 억제 규칙을 넣거나 인접 리팩터링으로 확장하지 않았다.
- 동적 패키지 추가·삭제 수 자체의 복원은 이번 한 품목 사례에서 검증하지 않았다. 전체 견적 입력 보존 완료로 읽지 않는다.

## 측정 범위와 남은 것

- 직접 입력한 필드 수와 중복 입력, 페이지 이동·패널 전환을 구분해 기록한다.
- 네트워크 대기·AI 도구 호출 시간은 사람의 작성 시간으로 계산하지 않는다.
- F01-03 입력량 30% 감소는 같은 조건의 개선 전 완료 흐름과 비교해야 한다. 개선 전 흐름이 손실로 중단되어 이번 한 사례만으로 감소율을 확정하지 않는다.
- 사람 5사례 작성 시간 및 실제 Fold 검증은 별도로 남긴다.
