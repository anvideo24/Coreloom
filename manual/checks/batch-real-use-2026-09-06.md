# 실사용 확인 — 한 번에 따라 하는 순서

> **지금은 시험 준비만 완료. 실제 시험은 아직 시작하지 않았습니다.**
> 확인할 때는 이 문서 하나로 순서를 따라가고, 결과는 연결된 기존 체크리스트에 기록합니다.

추가 확인: [작성·검토·매뉴얼 이어 쓰기](operating-ux-continuity-2026-09-06.md)의 업무·비용 초안, 승인함 상세 복귀, 접힌 과거 기록 열기는 아래 1·3·4단계에서 함께 확인합니다. 자동 시험 통과와 실기기 확인은 별도입니다.

## 오늘 어디부터 할까?

| 순서 | 할 일 | 준비물 |
| --- | --- | --- |
| 1 | PC에서 메뉴·매뉴얼·지도 읽기 | 로그인된 개발 화면 |
| 2 | 같은 화면을 4K·폴드에서 보기 | 실제 모니터·실제 폴드 |
| 3 | 고객사·견적 초안과 AI 입력 이어 쓰기 | 가상 입력, 기존 개인 초안 없는 시험 탭 |
| 4 | 승인 대상을 찾고 판단하기 | 진행자가 준비한 가상 사례 |
| 5 | 저장·오류·권한 경계 확인 | 담당자와 격리된 개발 시험 환경 |

**1~2는 읽기·이동부터, 3은 미전송 초안까지.** 실제 저장·AI 전송·권한 변경·승인/반려는 5번의 별도 확인 없이 실행하지 않습니다. 이 체크리스트 작성 승인은 시험 실행 승인이 아닙니다.

## 시작 전 — 네 칸만 확인

- [ ] **버전:** 시험 화면의 코드 버전을 확인합니다. 준비 기준은 PR #117 병합 코드 `79bd261`이며, 시험 당일 실행 버전을 다시 기록합니다.
- [ ] **데이터:** 실제 고객 자료 대신 시험용 가상 자료만 씁니다. 가상 목록이 없으면 준비 대기로 남깁니다. 이 문서가 데이터를 생성하지는 않습니다.
- [ ] **기기:** PC 일반 / 4K / 폴드 닫힘 / 폴드 펼침을 구별합니다. 브라우저·화면 배율·실제 CSS 화면 폭도 함께 기록합니다. 4K 모니터와 3840 CSS 픽셀은 같은 뜻이 아닙니다.
- [ ] **안전:** 사용 중인 초안·대화는 건드리지 않습니다. 실제 이메일·계좌·고객명·폴더 주소·접속 주소·쿠키가 보이는 캡처는 공개 기록에 올리지 않습니다.

로그인이 막히거나 버전·자료가 다르면 **그 자리에서 중단**합니다. 시험을 위해 운영 서버를 끄거나 DB 설정을 바꾸지 않습니다.

## 1. PC — 매뉴얼과 길 찾기

### 매뉴얼 읽기

1. 매뉴얼 홈 → 일하는 방식 → 차례의 제목 하나를 엽니다.
2. 문서 정보를 열었다 닫고, 진행 현황의 긴 표를 넘겨 봅니다.
3. 개선 목표·검증 현황에서 기능 하나의 체크리스트를 엽니다.

- [ ] 제목이 가려지지 않고, 표만 그 안에서 가로로 움직입니다.
- [ ] 기능 목록 → 체크리스트까지 선택 횟수를 적습니다. **목표: 2회 이내**, PC·휴대폰 각각 측정.
- [ ] 브라우저 **200% 확대**에서도 주요 버튼·경고·본문이 잘리지 않습니다. 끝나면 원래 배율로 돌립니다.

기록: [매뉴얼 읽기](manual-reading-2026-09-06.md), F07-01·06. 다른 환경의 결과를 같은 환경의 통과로 읽지 않는지도 확인합니다(F07-03).

### 업무 지도·시스템 구조도

1. 업무 지도에서 주 흐름과 보조 업무를 펼치고, 하나의 `화면으로` 링크를 연 뒤 돌아옵니다.
2. 시스템 구조도의 다섯 항목을 각각 열고, 같은 항목을 다시 눌러 닫습니다.
3. 설명을 읽은 뒤 대표가 **원본 파일 위치 / AI 조회와 실행의 차이 / Recho 연결 방식**을 자기 말로 설명합니다. 답을 먼저 알려주지 않습니다.

- [ ] 선택한 항목의 설명을 바로 찾고 기존 화면으로 이동할 수 있습니다.
- [ ] 구조도 다섯 항목 **5/5** 탐색, 이해도 세 질문 **3/3** 정답을 각각 기록합니다.

기록: [업무 지도](work-map-2026-09-06.md), [구조도 SM-06·09](system-map-2026-09-06.md). 마지막 재진입·임시 화면 폭 원복 미확인도 이번에 확인합니다.

## 2. 4K·폴드 — 같은 화면을 기기별로 한 바퀴

**기기마다 이 순서:** 대시보드 → 매뉴얼/지도 → 고객사·견적 → 승인함·상세 → AI 패널.

| 확인 | 볼 곳 |
| --- | --- |
| [ ] 페이지 가로 넘침·조작 가림·겹침 0건 | 네 환경 모두. 표 내부 스크롤은 페이지 넘침과 구분 |
| [ ] 긴 제목·한글 줄바꿈·경로가 읽힘 | 승인 목록·상세, 매뉴얼 차례, 폴더 선택 목록 |
| [ ] 넓은 화면 공간 활용 | 운영 화면은 좌우 공간 사용, 긴 매뉴얼 본문은 읽기 폭 유지 |
| [ ] 내비와 AI 패널 동시 사용 | 내비 접힘/열림 각각 AI 열기·닫기, 본문과 버튼 가림 확인 |
| [ ] 폴드 키보드를 올려도 입력·닫기·전송이 보임 | 닫힌 화면과 펼친 화면 각각. AI 버튼과 하단 메뉴 겹침 0건 |
| [ ] 이미지 추가·모델·전송 한 행 유지 | AI 패널, 특히 폴드 닫힘. 이 단계에서는 전송하지 않음 |
| [ ] 터치와 키보드로 닫고 다시 열 수 있음 | 작은 화면의 배경 차단, PC의 Tab·Escape와 초점 복귀 |

각 칸에 **기기별 결과**를 남깁니다. 한 기기만 보고 전체 완료로 체크하지 않습니다. 자동 대비 계산은 담당자가 확인하고 사람은 글자가 읽히는지 확인합니다.

같은 캡처·측정 한 번을 [셸 S01·04~09](shell-agent-responsive-2026-09-05.md), [고객사·폴더](sales-folder-ux-2026-09-06.md), [승인함 AP-07](approval-inbox-2026-09-06.md), [상세 AD-07](approval-detail-2026-09-06.md), F07-06에 연결합니다. 같은 시험을 따로 반복할 필요는 없습니다.

## 3. 초안 — 닫아도 남아 있는가?

### 고객사·견적

고객사 시험 폼에는 가상 상호와 선택 정보, 견적 시험 폼에는 서로 다른 **3품목·설명·메모·마진·운영비·수동 금액**을 넣습니다. 처음 입력값을 비공개 시험 기록으로 남긴 다음 아래 순서로 대조합니다.

| 동작 | 고객사 PC / 휴대폰 | 견적 PC / 휴대폰 |
| --- | --- | --- |
| 닫기 → 재열기 | ☐ / ☐ | ☐ / ☐ |
| 새로고침 | ☐ / ☐ | ☐ / ☐ |
| 다른 화면 → 복귀 | ☐ / ☐ | ☐ / ☐ |
| 저장 실패 → 복구 | 별도 시험 / 별도 시험 | 별도 시험 / 별도 시험 |

- [ ] 입력 손실·다른 폼의 값 혼입 **0개**. 품목 개수·순서도 비교합니다.
- [ ] 견적 중간/첫 품목 삭제, 빈 품목 추가 직후에도 재열기·새로고침 결과가 같습니다.
- [ ] 시험용 초안만 `이 초안 버리기`로 끝내고, 재열기·새로고침 때 되살아난 값 **0개**를 확인합니다. 개인 작업 초안은 삭제하지 않습니다.

기록: [견적 QD·QR 기록](quote-draft-flow-2026-09-06.md), F02-01·02. 원래 F02-01은 **2폼 × 2기기 × 4동작 = 16조합**입니다. 지금의 12개 비장애 조합만으로 16/16 통과를 표시하지 않습니다. 폴드 닫힘/펼침은 화면 검증에 각각 적되 16조합의 분모를 임의로 늘리지 않습니다.

### AI 입력·설정 초안

- [ ] 미전송 문구를 넣고 패널 닫기·재열기·새로고침: 같은 대화·입력·모델로 돌아옵니다.
- [ ] 설정 초안 변경 → 다른 화면 이동: 경고에서 `계속 편집`하면 초안이 남습니다. 시험 변경만 `버리고 계속`으로 버립니다. 실제 저장은 별도입니다.
- [ ] 폴더 선택은 가상 시험 폴더만 추가·제거하고 **설정 저장 없이** 마칩니다. 주소 직접 타이핑 없이 선택 목록을 이해할 수 있는지 봅니다.

기록: [셸 S06·07](shell-agent-responsive-2026-09-05.md), [폴더 선택 기록](sales-folder-ux-2026-09-06.md). 첨부 업로드·AI 응답 생성·재연결은 다음 별도 준비 항목입니다.

## 4. 대표 판단 — 정답을 보기 전에

진행자는 기존 가상 사례와 지시문을 준비합니다. **이 안내에는 정답을 싣지 않습니다.** 준비된 시험 화면이 없으면 진행하지 않고 대기로 남깁니다. 결과를 클릭해 실제 확정하지 말고 말로 답합니다.

| 시험 | 대표가 할 일·기록할 수치 |
| --- | --- |
| [ ] 승인 대상 찾기 | 가상 대기 10건에서 지시한 대상·근거 열기 5회. 중앙값 **15초 이내**, 오선택 **0건** |
| [ ] 승인 판단 | 고정 5사례의 승인/반려와 이유 답하기. 오판 **0건**, 판단 시간은 전후 비교 |
| [ ] 확정 전 정보 대조 | 같은 5사례의 대상·금액·증빙·확정 후 결과 **20/20** 대조. 위 판단 시험과 증거 공유 가능 |
| [ ] AI 상태 구분 | 섞인 6사례를 답변/초안/반영 완료로 분류. **6/6** 정답, 각각 **5초 이내** |

진행자가 읽을 자료: `docs/quality/approval-search-cases.md`, `approval-review-cases.md`, `ai-status-classification-cases.md`. 응시자는 시험 전에 열지 않습니다. 연습은 별도 사례로 하고, 사람 조작 시간과 네트워크 대기는 분리합니다.

기록: AP-08·09, AD-08·09, F03-01~03, F04-01. 처음 보여주는 시안이나 모의 사례와 실제 서버 화면 검증은 구분합니다. 답변만 하는 AI를 실제 기록 반영 사례로 간주하지 않습니다.

## 5. 담당자와 별도 준비 — 지금 누르지 않는 것

| 남은 시험 | 시작 조건·완료 기준 |
| --- | --- |
| 고객사 → 견적 저장·입력량 | 확인된 개발 DB·가상 자료 생성 범위 승인. 외부 화면 왕복/중복 입력 0회, 저장·재조회 일치. F01-03의 30% 감소는 동등한 개선 전 기준이 없으면 미측정 유지 |
| 저장 실패·응답 유실 | 운영 서버 중단 없이 격리 환경에서 장애 주입. F02 남은 4조합·QR-04 복구 조작·F02-03 실제 저장 결과 1건 대조 |
| AI 전송·이미지·재연결 | 가상 이미지/문구·구독 사용 범위 확인. 전송 후 입력 비움, 메시지 복사, 명시적 중지와 연결 단절 구분, 같은 대화 복귀. S07 및 F04-04 실제 흐름 |
| AI 결과 확정 후 재조회 | 별도 개발 시험 승인. 확정·반려 각각 ID·내용·상태·이력 서버 재조회 일치(F04-03). 외부 업무 자동 실행은 시험하지 않음 |
| 세 유형 업무 저장 | 대상 스키마 직접 확인 후 가상 업무 생성 승인. 회사/자체 사업/고객사 프로젝트 **3/3** 등록·재조회(F06-01). 문서의 과거 마이그레이션 상태로 재실행하지 않음 |
| 무권한 접근·초안 분리 | 시험 계정/별도 세션 준비, 현재 대표 세션은 유지. 매뉴얼 무권한 열람 0건(F07-05), 다른 사용자·폼 초안 노출 0건(F02-04) |

가상 자료 생성·삭제, 권한 저장, 확정·반려, 장애 주입은 **대상과 동작을 적어 별도 확인**한 후 진행합니다. 이메일 발송·금액 확정·계약 체결·운영 DB 변경은 이 일괄 UX 시험에서 자동 실행하지 않습니다.

## 결과는 이렇게 남긴다

**한 줄 양식:** `기존 검사 ID / 날짜·코드 버전 / 기기·브라우저·배율·실측 폭 / 시도 수·성공 수 / 측정값 / 통과·실패·미측정 / 비공개 증거 식별자`

1. 연결된 기존 체크리스트에 측정 범위를 추가합니다. 오래된 실패·부분 확인은 지우지 않습니다.
2. F01~F07에 해당하면 담당자가 `docs/quality/verification-results.json`에 증거를 덧붙입니다. 이 문서의 체크 개수로 앱 통과율을 계산하지 않습니다.
3. 준비가 없어서 못 한 것은 실패나 0초가 아니라 **미측정 + 필요한 준비**로 남깁니다.
4. 예상과 다르면 해당 시험을 멈추고 재현 단계·가상 입력·기기를 기록합니다. 같은 시도를 세 번 반복하거나 임의로 수정·확정하지 않습니다.

이 문서는 기존 [개선 계획](../../docs/superpowers/plans/2026-09-05-measurable-improvements.md)과 개별 기록의 **실행 순서표**입니다. 목표·판정 규칙을 새로 정의하지 않으며, 2026-09-06 이후 추가된 작업은 별도로 연결해야 합니다.
