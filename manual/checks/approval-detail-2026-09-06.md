# 승인 상세 확인 기록

통합 상태는 [PR #117](https://github.com/anvideo24/Coreloom/pull/117)에서 확인한다. 승인함과 합친 코드 `7be4d57`의 전체 74파일 490개 시험·타입 검사 통과. 아래 개별 검사 이력과 미측정 실제 화면·대표 판단 항목을 그대로 보존하며 CI·main 병합이 실기기 검증을 대신하지 않는다.

## 목표와 범위

대상·금액을 먼저 읽고, 기록된 증빙/참고와 확정 후 결과를 구분한다. 빠른 승인 자체가 아니라 잘못된 대상·근거로 결정하지 않는 것이 목표다.

- 대상: 비용·매출·입금·계약·AI 제안·에이전트 작업 상세 여섯 종류.
- 보존: 실제 승인·반려 조건, 대표 인증, 필수 체크·반려 사유·결과 입력, 확정된 기록 보호.
- 제외: DB·마이그레이션·서버 재기동·실제 승인/발송, 환불 흐름 변경, 외부 CI·main 병합.
- 작업 가지: `codex/approval-detail-clarity`. 이전 승인함 작업은 `codex/approval-inbox-clarity`에 별도 보존한다.
- 검증 코드: `084003da44040684f997131b7f030f1929e3fb51`. 아래 결과는 이 작업 가지의 로컬 검사이며 main 병합·실기기 검증은 아니다.

## 후속 자동 시험 — 실제 페이지 연결

기존 AD-05·06의 코드 대조를 보완하기 위해 여섯 상세 페이지 함수를 직접 호출하고 반환된 화면을 jsdom에서 렌더링한다. 인증·자료 조회·서버 액션과 대화 등 범위 밖 하위 화면만 대역으로 바꾸며, 확인 카드와 요약 계산은 실제 코드를 사용한다. 모든 자료는 가상 값이다.

대상 제품 코드 기준은 `d0252ce`이며 제품 코드는 수정하지 않는다. 자동 시험 원본은 `apps/web/tests/approval-detail-pages.test.tsx`다. 이 검사는 CSS 배치·실제 로그인·HTTP 이동·서버 제출·DB 저장을 검증하지 않는다. 기존 AD-01~09 이력과 F03 판정은 덮어쓰지 않는다.
