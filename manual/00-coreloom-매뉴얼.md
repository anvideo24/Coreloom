# Coreloom 운영 매뉴얼

## 이 매뉴얼의 목적

Coreloom은 강의·앱·온라인 서비스를 함께 운영하는 1인 창업자와 AI 에이전트 팀을 위한 비공개 운영 본부다. 회사 설립 준비, 고객사 수주·계약·청구, 매출·비용, 프로젝트 진행, 관련 기록의 근거 확인을 한 흐름으로 관리한다. 이 문서는 시스템 설명의 정본이며, 미래 배포본의 관리자 화면에서도 같은 원본을 표시한다. 공용 제품 규칙과 일하는 방식은 GitHub `anvideo24/working-method`다. Coreloom만의 지금 규칙은 [RULES.md](../RULES.md), 이 프로젝트 기동은 [AGENTS.md](../AGENTS.md)다.

## MVP의 업무 흐름

1. 대표가 개인사업자 설립 준비 항목과 증빙을 등록한다.
2. 고객사와 담당자를 등록하고, Recho 메일·통화·회의 기록을 필요할 때 프로젝트에 연결한다.
3. 대표가 견적서를 작성·수정해 PDF로 발송하고, 전자서명 또는 날인 계약 원본을 보관한다.
4. 대표와 AI 에이전트가 프로젝트 업무·일정·진행률·분할 청구 일정을 관리한다.
5. 대표가 청구·세금계산서·입금 상태와 사업별 매출·비용을 확인한다.
6. AI 에이전트가 제안한 합의·다음 할 일·위험을 Recho 근거와 함께 보고, 대표가 확정 또는 반려한다.

세부 MVP 범위는 [docs/mvp-scope.md](../docs/mvp-scope.md)를 따른다.

## 운영자 기본 원칙

- 금액과 승인 상태는 확정 전에 반드시 거래처·프로젝트·증빙을 확인한다.
- 잘못된 기록은 덮어쓰지 말고 정정 이력을 남긴다.
- 개인 정보와 재무 정보는 필요한 역할에게만 보이게 한다.
- 화면상 숫자와 실제 저장 데이터가 다르면 기록을 수정하기 전에 변경 이력과 권한을 먼저 확인한다.
- AI 에이전트의 결과는 대표가 확인·승인하기 전까지 확정된 거래, 공개물 또는 회사 결정으로 취급하지 않는다.
- Recho 기록의 최신 발언은 현재 결정의 후보일 뿐이다. 앞뒤 시간 맥락과 원문을 확인한 뒤에만 공식 결정으로 확정한다.

## 대표 로그인과 데이터 기반

업무·비용의 `저장 중…`에는 추가 전송을 막는다. 저장 결과를 확인하지 못하면 입력은 작성창에 남고 `업무 목록 확인` 또는 `비용 목록 확인`으로 저장 여부를 먼저 확인한다. 오류가 났다고 미저장으로 단정하거나 바로 다시 보내지 않는다. 안내가 나온 같은 창에서는 재전송을 막지만 다시 열거나 새로고침한 뒤의 중복까지 보장하지는 않는다.

매출 등록과 사업 등록도 제목 옆 `닫기`로 닫았다가 같은 탭에서 이어 쓴다. 두 초안은 서로 분리하며 `이 초안 버리기`를 확인하거나 저장에 성공하면 해당 초안만 지운다. 오류가 나면 재열어 복원할 수 있으나 이 두 폼은 아직 작성창 안의 오류 안내 대상이 아니다.

업무·일정의 `업무 이력`에서 업무명·상태·유형으로 목록을 좁힌다. 세 조건은 함께 적용하며 `필터 초기화`로 전체 목록을 다시 본다. 검색 중에도 위쪽 `기한별 할 일`은 그대로 보인다. 표시 건수는 필터 결과이며 전체 업무 건수와 다르다.

업무·비용 작성창에서도 상단의 `닫기`로 나갔다가 같은 탭에서 입력을 이어 쓴다. 업무 유형과 연결 대상도 함께 복원하며, `이 초안 버리기`는 확인한 뒤 지운다. 저장에 실패했다고 초안을 지우지 않는다. 탭의 임시 보존이므로 다른 기기로 옮겨지지 않고, 서버에 업무·비용이 저장됐다는 뜻도 아니다. 기존 초안과 같은 필드별 보관 한도를 적용한다.

승인함에서 검색·종류를 고르고 상세를 검토한 뒤 돌아오면 같은 탭의 탐색 조건을 이어 쓴다. 보던 항목이 남아 있으면 그 항목을 찾고, 이미 처리되어 사라졌다면 현재 목록을 기준으로 계속 검토한다. 새 탭·다른 기기에는 이어지지 않으며, 임시 저장소 사용이 차단되면 복원이 보장되지 않는다. 검색어를 주소나 서버에 남기지 않는다.

고객사·견적 작성창은 상단 `닫기`로 닫는다. 본문을 스크롤해도 닫기 버튼은 남고, 다시 열면 기존 초안을 이어 쓸 수 있다. 닫기는 초안 버리기가 아니다. 빈 목록의 첫 생성 버튼은 큰 모니터에서도 내용에 맞는 폭으로 표시한다.

견적의 `패키지 추가`·`패키지 삭제` 직후에도 품목 목록을 초안에 남긴다. 같은 탭에서 다시 열거나 새로고침하면 순서와 품목별 입력·설명·수동 금액 잠금·마진·운영비를 복원한다. `이 초안 버리기`를 확인하면 기본 빈 품목으로 돌아간다. 이는 브라우저 탭의 임시 보존이며 서버에 견적 버전을 저장하는 것과 다르다. 다른 기기와 동기화하지 않으며 품목 컬렉션 초안은 64,000자, 일반 필드는 8,000자 이내다. 한도를 넘는 값의 보존은 보장하지 않는다.

새 견적 저장 중 연결이 끊겨 결과가 불확실하면 **같은 탭에서 같은 내용으로 재시도**한다. 다시 열거나 새로고침해도 이전 저장 요청 번호를 이어 써, 이미 저장된 견적은 기존 결과로 연결한다. 실패 뒤 내용을 바꾸면 재전송을 막고 안내하므로 먼저 견적 목록에서 저장 여부를 확인한다. 이미 저장됐다면 그 견적을 열어 수정하고, 별도 견적을 새로 만들 때만 `이 초안 버리기`로 이전 시도를 끝낸다. 브라우저가 요청 정보를 보존하지 못하면 저장을 보내지 않는다. 다른 탭·기기, 로그아웃·탭 종료·저장소 삭제 후, 기존 견적의 새 버전 저장은 이번 재시도 보장에 포함되지 않는다. 실제 기기·서버 확인과 자동 시험 범위는 [QR 체크리스트](checks/quote-draft-flow-2026-09-06.md)에서 구분한다.

저장 오류가 나면 새 견적 작성창의 입력은 그대로 남는다. 요청을 보내지 못한 경우와 **저장 여부 확인이 필요한 경우**를 나눠 안내한다. `다시 시도`로 같은 내용을 보내거나 `견적 목록 확인`으로 저장된 견적을 찾는다. 목록을 확인한다고 초안이 삭제되지는 않는다. 미확정 요청은 다시 열어도 안내가 남으며, 수정한 내용의 재전송이 막히면 먼저 목록을 확인한다. 서버 오류의 기술적인 원문은 표시하지 않는다.

- Coreloom은 Neon Auth의 대표 이메일 로그인과 서버 측 허용 이메일 검사 두 단계를 함께 사용한다. 인증은 됐지만 허용 이메일과 다른 계정은 운영 화면을 볼 수 없다.
- 개발 PC의 정식 기동은 `apps/web`에서 `npm run up`이다. 이 명령은 `main`이 깨끗하면 최신을 받고, 예전에 켜 둔 3000번 서버를 끈 다음 PC와 휴대폰용 주소를 같이 연다. 로컬 서버는 HTTP만 쓰며 PC 브라우저는 `http://127.0.0.1:3000/dashboard`를 연다. `/api/auth`는 PC의 `127.0.0.1`과 `localhost` Origin을 Neon이 기본으로 받는 `http://localhost:3000`으로 같게 본다. 휴대폰 Funnel은 HTTPS `:8443`이 로컬 3000으로 연결된다. Funnel이 바깥으로 열 수 있는 포트는 `443`, `8443`, `10000`뿐이다. Coreloom은 `:8443`을 쓰고, 숫자 없는 `443`은 끈다. `:10000`은 다른 앱이므로 건드리지 않는다. 휴대폰에서는 Tailscale 앱을 끈 채 모바일 데이터로 `:8443` 주소만 연다. 로그인 뒤 좁은 화면에 **웹앱으로 설치** 칩이 보이면 눌러 홈 화면에 둔다. Android·Chrome은 설치 프롬프트, iOS Safari는 공유 → 홈 화면에 추가 안내를 쓴다. 이미 단독 앱으로 열린 때는 칩을 숨긴다. PC만 열 때는 `npm run dev`로도 된다. `npm run dev`를 켤 때도 `main`이 깨끗하면 최신을 먼저 받는다. Funnel 주소와 실제 호스트 이름은 채팅·로그·커밋·PR에 넣지 않는다. 이 주소는 대표만 쓰고 다른 사람에게 보내지 않으며, 로그인된 대표 계정만 들어올 수 있다. Funnel 주소는 localhost가 아니므로, 휴대폰 로그인이 막히면 Neon Console → Auth → Configuration → Domains에 `:8443`이 붙은 HTTPS 주소를 넣는다. `/api/auth`는 휴대폰 Funnel `:8443` Origin도 Neon이 받는 localhost Origin으로 바꿔 넘긴다. 다른 사이트 Origin은 바꾸지 않는다. `/setup`은 이 PC의 localhost에서만 저장된다. PC가 꺼져 있거나 서버가 꺼져 있으면 휴대폰에서도 열리지 않는다. 개발 서버를 바꾼 뒤에는 다시 켠다.

- `/expenses`에서 비용 원장 목록을 보고 헤더의 `+`로 등록한다. 계정과목은 `/accounts` 마스터의 비용 과목에서 고르며, 매입처 고객사(거래 유형이 매입 또는 매출·매입인 고객사) 또는 매입처 이름을 적을 수 있다. 고객사를 고르고 이름을 비우면 상호로 채운다. 고객사 프로젝트 또는 앱·구독 사업에 비용을 연결한다. 금액은 통화(KRW), 발생일, 지급 예정일, 확정 상태를 함께 가지며, 연결하지 못한 건은 미분류로 표시한다. 비용 확정은 대표 승인 뒤에만 처리하며 확정된 금액은 덮어쓰지 않는다. 자동 이체·급여·세금계산서 발행은 이 기능에 포함되지 않는다. 개발 DB에는 0026–0028 마이그레이션이 필요하다.
- `/accounts`에서 계정과목 목록을 보고 헤더의 `+`로 과목을 추가한다. 자산·부채·자본·수익·비용 구분을 두며, 처음 열면 기본 과목이 채워진다. 매출·비용 원장은 수익·비용 과목만 고른다. 복식 분개·전표·세무 대행은 포함하지 않는다. 개발 DB에는 0028 마이그레이션이 필요하다.
- `/tasks`에서 업무 목록·기한별 일정을 보고 헤더의 `+`로 등록한다. 업무 유형은 회사 운영, 자체 사업, 고객사 프로젝트다. 회사 운영에는 고객사·프로젝트·사업을 붙이지 않고, 자체 사업에는 사업을, 고객사 프로젝트에는 고객사와 프로젝트를 연결한다. 고객사 없는 두 유형을 위해 가짜 고객사를 만들 필요는 없다. 기한과 완료 조건을 기록하며, 진행 중인 업무는 기한별 일정으로 보이고 활성 AI 에이전트 시스템 계정에 배정할 수 있다. 완료는 대표가 조건을 확인한 뒤에만 처리한다. 완료된 업무는 덮어쓰지 않으며 배정도 바꾸지 않는다. Recho 캘린더 연동은 이 기능에 포함되지 않는다.
- `/agents`에서 AI 에이전트 목록을 보고 헤더의 `+`로 등록한다. 사람 Neon 계정과 다른 시스템 계정으로 이름, 목적, 허용 업무(자료 조사·초안 작성·업무 업데이트·승인 요청 초안), 접근 범위, 일하는 방식·답변 방식·절차·지침, 구독 모델(Claude/GPT·Codex/Cursor), 능력(기록 저장·외부 발송·금액·계약 확정·권한 변경, 기본 꺼짐), 상태를 구역(연결·기본·지침)·2열 패널로 보관한다. 대표가 요청·입력·결과와 승인·반려를 이력으로 남기며, 결정된 이력은 덮어쓰지 않는다. 대기 중인 요청은 `/approvals`에도 모인다. 능력에 켠 항목만 실행할 수 있다. 로그인과 자동 실행은 포함하지 않는다.
- `/timeline`에서 시간순 근거 목록을 보고 헤더의 `+`로 Recho 메일·통화·회의를 프로젝트의 근거로 연결한다. 원문 식별자, 발생 시각, 연결 이유를 보관하고 시간순으로 보여 주며, 원문 링크가 있으면 새 창에서 연다. Coreloom은 원문을 복제하거나 수정하지 않는다. Recho API 동기화는 이 기능에 포함되지 않는다.
- `/proposals`에서 미확정·결정 이력을 보고 헤더의 `+`로 근거 기록에 연결된 AI 제안 초안을 등록한다. 종류는 현재 합의·다음 할 일·위험이며, 근거가 없으면 등록하지 않는다. 대표가 원문을 확인한 뒤에만 확정 또는 반려하고, 확정 전에는 공식 결정으로 보이지 않는다. 결정된 제안은 덮어쓰지 않는다. 자동 생성, 계약 체결, 외부 발송은 이 기능에 포함되지 않는다.
- `/admin/manual`은 카테고리 카드로 고르는 입구다. 규칙(공용 규칙·이 제품 규칙), 일하는 방식(일하는 방식·배운 것), 운영(운영 설명·시스템 진행 현황·역할별 운영 절차·변경 기록)으로 나누고, 긴 원본은 칸을 고른 뒤에만 연다. 공용 문서는 `working-method` 저장소 원본을, 나머지는 이 저장소 원본을 읽기 전용으로 본다. 배포 버전·매뉴얼 원본 커밋을 함께 표시한다. 시스템 진행 현황에서는 기능별 구현 상태를 표로 추적하며, 기능이 추가되거나 상태가 바뀌면 같은 커밋에서 갱신한다. 화면에서 편집하지 않으며, 권한 없는 계정은 볼 수 없다.
- 대표 계정은 Neon Console에서 직접 만든다. 계정에 비밀번호가 없는 경우 `/auth/forgot-password`에서 대표 이메일로 설정 링크를 요청한다. 공개 가입은 켜지지 않으며, 이메일·비밀번호·연결 문자열·쿠키 비밀값은 저장소나 매뉴얼에 기록하지 않는다.
- 스키마를 바꾸면 같은 변경에 drizzle 마이그레이션을 둔다. 개발 PC에서는 `apps/web`에서 `npm run db:migrate`(또는 `tsx scripts/migrate.ts`)를 돌린다.
- **적용 여부는 문서가 아니라 스키마에 물어본다.** 「몇 번까지 적용됐다」를 손으로 적어 두면 실제와 어긋난다(2026-09-04·09-05 두 번 어긋났다). 돌리기 전에 대상 DB의 컬럼·테이블을 직접 조회해 확인한다.
- **마이그레이션은 확인된 DB에만 돈다.** `npm run db:migrate`는 `CORELOOM_DATABASE_HOST`에 적힌 접속 대상과 `DATABASE_URL`이 가리키는 곳이 같을 때만 실행된다. 값이 없으면 거부하고, 지금 어디를 향하는지 보여 주며 **Neon Console에서 `ai-development` 브랜치가 맞는지 확인한 뒤 적으라고** 안내한다. 코드가 대신 채우지 않는다 — 사람이 확인하는 자리다.
- ⚠️ **이 관문이 못 잡는 것을 알아 둔다.** 확인한 뒤에 대상이 바뀐 것은 잡지만, **처음부터 운영 DB 주소를 넣고 그대로 확인해 버리면** 막지 못한다. 그래서 확인은 연결 문자열이 아니라 Neon Console을 보고 한다.
- 클라우드 에이전트를 쓴다면 `CORELOOM_DATABASE_HOST`도 환경 Secrets에 넣는다. 없으면 기동 중 마이그레이션이 거부되어 서버가 안 뜬다.
- 스키마 변경은 `ai-development`에서 먼저 검증한다. `production` 적용과 복구는 대표의 그 시점 승인 없이는 실행하지 않는다.
- 배포본 포장은 Next `output: "standalone"`과 저장소 뿌리 `Dockerfile`이다. 컨테이너 진입점은 `apps/web/server.js`이며, `.env*`는 이미지에 넣지 않는다. 절차 정본은 `docs/operations/deploy-packaging.md`다. 호스팅 공급자 선정과 Vercel 연결은 그 문서 범위 밖이다.
- 백업은 자동화하지 않는다. 운영 변경 전후에 `docs/operations/neon-branch-and-backup-runbook.md`의 수동 절차를 따른다.

## 에이전트 구독 대화

- 답변 아래의 보조 문구에서 `AI 답변`, `AI 응답 실패`, `AI 응답 중지됨`, `AI 응답 상태를 확인하지 못함`을 구분한다. 함께 표시되는 `업무 기록 변경 없음`은 회사 기록의 저장·수정·확정·발송을 하지 않았다는 뜻이며, 대화 이력 자체의 저장과는 다르다. 답변 본문에 “반영했습니다”라고 적혀도 실제 처리 증거가 되지 않는다. 새 명시적 중지만 별도 상태로 남기며, 과거 `failed` 기록은 본문으로 중지 여부를 추측하지 않는다. 전역 패널과 에이전트 상세에서 동일하게 표시하고, 다시 연 대화에도 저장된 상태를 사용한다. 실제 기기 확인은 누적 실사용 시험 때 진행한다.

- 설정을 바꾼 뒤 다른 대화 화면·에이전트·내부 페이지로 이동하면 `저장하고 계속`, `버리고 계속`, `계속 편집`을 고른다. 저장 실패나 권한 확인 취소가 있으면 이동하지 않는다. 대화 방식 저장 후 자료 접근 저장만 실패했다면, 이미 저장된 대화 방식은 유지하고 실패한 부분만 다시 저장한다. 패널을 닫기만 하면 설정 초안은 유지된다. 새로고침·브라우저 닫기는 기본 이탈 경고이며 경고 안의 즉시 저장은 지원하지 않는다.

- 같은 브라우저 탭에서는 마지막 대화·선택 모델·작성 중인 글·첨부 목록을 복원한다. 패널을 닫아도 새 대화를 만들지 않는다. 새 탭은 해당 에이전트의 최근 대화를 열고, `새 대화`를 누른 경우에만 빈 대화를 유지한다. 작성 중 입력은 탭의 세션 저장소에 보관되므로 다른 기기와 동기화되지 않는다.
- `＋ 이미지`로 여러 장 선택하거나 입력창에 붙여넣고, 패널에 파일을 드롭할 수 있다. PNG·JPG·WebP 정지 이미지, 장당 8MB·최대 6장이다. 서버에서 실제 형식을 검사하고 메타데이터를 제거한 최대 2048px WebP로 변환한다. 원본 증빙 보관 기능이 아니므로 원본은 문서함에 별도로 보관한다.
- 첨부 미리보기의 `제거`는 보내기 목록에서만 뺀다. 보낸 이미지는 대화에서 다시 열 수 있다. 이미지는 서버 PC의 사용자 전용 Coreloom 폴더에 비공개 보관하고, DB에는 이미지 식별자만 남긴다. 에이전트당 보관 한도는 256장이다. 자동 삭제는 하지 않으며 서버 PC가 바뀌면 파일도 별도로 이관해야 한다.
- 대화의 최근 첨부 최대 6장을 선택한 GPT·Claude 구독 실행기에 실제 이미지로 전달한다. 오래된 첨부가 입력에서 제외된 경우 모델에 명시한다. 이 기능은 직접 첨부한 이미지에 한하며 문서함 PDF·이미지 자동 읽기 권한을 추가하지 않는다.
- 전송 즉시 글과 첨부를 입력창에서 비우고 대화에 표시한다. 응답 실패·중지 시 별도로 보관한 글과 첨부를 복원해 재전송할 수 있다. 동일 요청 재시도는 요청 식별자로 중복 저장·생성을 막는다. 응답 중에는 입력을 잠그고, 모바일 키보드 Enter는 줄바꿈, 데스크톱 Enter는 전송·Shift+Enter는 줄바꿈이다. 이전 메시지를 읽는 동안에는 아래로 강제 이동하지 않고 `새 답변 보기`를 제공한다. 사용자 메시지·완료 답변·실패 안내 모두 복사 버튼을 제공한다.
- 브라우저 연결 끊김·새로고침은 모델 중지로 처리하지 않는다. PC 프로세스에서 진행 중인 답변을 계속 생성하고, 같은 탭에서 다시 열면 요청 식별자로 상태와 저장된 답변을 복구한다. `중지` 버튼은 소유자가 보낸 별도 중지 요청으로만 실행되며, 실패 이력에는 사용자 중지와 생성 실패를 구분한다. PC 프로세스 자체가 종료된 경우까지 복구하는 영속 작업 큐는 아니며, 그 경우 다시 보내야 한다.
- 이미지 첨부와 요청 중복 방지에는 개발 DB 마이그레이션 0030·0031이 필요하다. 실제 적용 여부는 대상 스키마에서 확인한다.

- 전역 AI 패널과 에이전트 상세 페이지는 같은 대화 UI를 사용한다. 입력창에서 GPT(Terra/Mini) 또는 Claude(Sonnet/Opus)를 고른다. 제공자에서 해당 모델을 사용할 수 없거나 한도가 소진되면 오류로 알리며 유료 API로 전환하지 않는다.
- 실행 PC의 Codex는 ChatGPT 로그인, Claude는 Claude 구독 로그인이 필요하다. Cursor 직접 실행은 현재 준비 전이다. 이 PC에서만 구독 실행기를 호출하며 컨테이너 배포만으로 구독 로그인이 연결되지는 않는다.
- `지침 설정`에서 일하는 방식·답변 방식·절차·추가 지침과 기본 구독을 저장한다. 에이전트별로 저장하고 다음 답변부터 적용한다. 지침 변경으로 데이터 접근 권한이나 발송 능력이 생기지 않는다.
- 대화에는 입력한 메시지·이전 최대 40개 메시지·에이전트 지침·현재 화면 이름이 포함된다. 자료 조회 권한을 켜면 서버가 허용된 자료를 조회해 선택한 구독 모델에 전달한다. 다른 에이전트 대화는 자동으로 읽지 않는다. 대화 기록과 변경 이력은 대표 전용 DB에 남는다. 응답은 생성 완료 시 표시되며 토큰 단위 스트리밍은 아니다.

### 자료 조회 권한

- 에이전트 패널 또는 상세 페이지 → **지침 설정 → 자료 조회 권한**에서 견적서·고객사·프로젝트·업무·문서 목록·PC 폴더를 각각 켜고 저장한다. 새 에이전트는 모두 꺼짐이다. 이름이나 지침 문구로 권한이 생기지 않는다.
- ERP 조회는 현재 연결된 DB와 해당 대표의 워크스페이스에 한정한다. 프로젝트 지정 에이전트는 해당 프로젝트로 좁힌다. 앱·구독 사업 전용 에이전트의 고객사 ERP 조회는 아직 지원하지 않으며 차단한다. 이전 DB의 자료를 합치거나 대신 읽지 않는다.
- 견적 목록은 최신 버전의 제목·금액·유효기간, 상세 조회는 품목·메모를 읽는다. 고객사는 이름·업종·거래 구분만 제공하며 연락처·계좌는 제공하지 않는다. 문서는 목록·버전·메모만 제공하고 PDF·이미지 원본 해석은 지원하지 않는다. 목록은 한 번에 최대 20건이며 다음 페이지 조회가 가능하다.
- PC 폴더는 `폴더 선택`을 눌러 서버 PC의 시작 위치·하위 폴더를 탐색한 뒤 `이 폴더 추가`로 최대 8개 지정한다. 선택 목록에서 이름·경로를 확인하고 제거한다. 선택은 초안이며, 기존 조회 권한 확인·저장 전에는 AI에게 적용되지 않는다. 경로 직접 입력은 고급 항목에서 사용할 수 있고 같은 서버 검증을 거친다. 드라이브·홈 전체는 탐색 출발점일 뿐 등록할 수 없다. 경로는 서버 PC의 사용자 전용 설정 폴더에만 보관되며 Git이나 모델 프롬프트에 넣지 않는다. 원격 접속 중에도 접속 기기가 아닌 서버 PC 기준이다. PC가 바뀌면 다시 지정한다.
- 파일명 검색과 TXT·MD·CSV·JSON(UTF-8, 64KB 이하) 읽기를 제공한다. 파일당 본문은 최대 16,000자, 검색은 최대 40건/1,200항목/깊이5/4초로 제한한다. 전체 폴더를 다 읽었다고 간주하지 않는다.
- 드라이브·홈 전체, 인증·시스템 폴더, 숨김 경로, 심볼릭 링크·junction·하드링크, 폴더 밖 상대 경로는 차단한다. 비밀번호·토큰 등 비밀 패턴이 감지된 파일도 차단한다. 비밀 탐지가 완전한 내용 분류기는 아니므로 비밀이 섞인 폴더는 허용하지 않는다.
- 모델은 JSON 조회 계획만 반환하고 서버가 매번 권한을 다시 검사한다. 한 답변당 최대 2라운드·라운드당 3회 읽기만 실행한다. 쉘 실행·파일 수정·삭제·ERP 변경·외부 발송은 이 경로에 없다.
- 읽은 출처는 답변 하단에 붙고, 허용/실패 기록은 **최근 자료 조회 기록** 및 DB 감사 이력에 남는다. PC 절대 경로나 파일 본문은 감사 이력에 넣지 않는다. 권한을 꺼도 과거 대화에 이미 들어온 자료는 지워지지 않는다. 새 대화를 시작하면 이전 대화 내용이 입력에서 빠진다.
- `새 대화`는 이전 기록을 보존한 채 새로 시작한다. `대화 이력`에서 다시 연다. 생성 중 `중지`는 해당 호출을 취소하며 입력은 다시 보낼 수 있게 복원한다. 창을 떠나도 PC에서 생성은 계속된다.
- 대화 저장에는 `0029_agent_conversations`가 필요하다. 확인된 개발 DB에 `npm run db:migrate`로 적용한다. 운영 DB 적용은 별도다.

## 관리자 매뉴얼 화면

대표는 `/admin/manual`에서 규칙과 운영 설명을 읽기 전용으로 본다.

진행 현황·운영 설명에서는 현재 안내를 먼저 읽고, `과거 구현 기록 (원문 보존)`을 눌러 당시 기록을 펼친다. 과거의 ‘다음·병합 전’은 현재 지시가 아니다. 과거 제목 링크로 들어가면 해당 부분이 자동으로 열리며, 현재의 제한·미검증 안내는 접지 않는다.

- **홈은 고르는 입구다.** 카드 세 묶음(규칙·일하는 방식·운영)으로 나뉘고, 각 카드에는 한 줄 설명과 원본 파일 이름이 붙는다. 홈에 긴 원문을 펼치지 않는다.
- 카드를 고르면 그 원본이 열린다. 원본 화면 위에는 「매뉴얼 홈」으로 돌아가는 길이 있다.
- 운영 묶음의 [업무 지도](work-map.md)에서 고객사·프로젝트·견적·계약·청구·입금 확인의 관계를 본다. 항목을 한 번 눌러 역할·연결·주의를 펼치고 `화면으로`를 누르면 기존 업무 목록으로 이동한다. 좁은 화면에서는 선택한 항목 바로 아래에 설명이 열린다. 회사 준비·문서함·업무·AI 에이전트는 아래에서 따로 펼친다. 내용의 원본은 `manual/work-map.md`이며 실제 데이터·진행률·자동 실행을 나타내지 않는다.
- 운영 묶음의 [시스템 구조도](system-map.md)에서 회사 기록·원본 파일·AI 대화·외부 연결·운영 문서 다섯 가지의 저장 위치와 권한 경계를 본다. 처음에는 AI 설명이 열리며, 다른 항목을 누르면 설명이 바뀌고 같은 항목을 다시 누르면 닫힌다. 키보드 Tab으로 이동하고 Enter·Space로 여닫는다. 넓은 화면은 가로 다섯 갈래, 좁은 화면은 선택 항목 바로 아래에 설명을 표시한다. 선은 관계일 뿐 실시간 연결 상태나 자동 처리가 아니다. 내용은 `manual/system-map.md`에서 읽는다. 구현·검증 상태와 대표가 직접 확인할 두 항목은 [시스템 진행 현황](system-progress.md)의 SM-01~09에서 확인한다.
- 원본 문서의 `이 문서의 차례`에서 제목을 고르면 해당 절로 이동한다. 좁은 화면에서는 차례를 눌러 펼치며, 넓은 화면에서는 본문 옆에 둔다. 기능별 검증 현황처럼 별도 구성 요소를 포함한 화면은 기존 구성을 유지한다.
- 이 화면은 Markdown 원문을 렌더링한다. 화면용 HTML 사본을 별도 정본으로 두지 않는다.
- 공용 규칙·일하는 방식·배운 것은 `working-method` 저장소에서 읽는다. 그 저장소는 Coreloom과 같은 부모 폴더에 클론한다. 찾지 못하면 그 칸은 「저장소가 아직 없다」고 밝히고, 빈 화면처럼 보이게 하지 않는다.
- 상단의 `문서 정보`를 펼치면 배포 버전과 매뉴얼 Git 커밋을 확인할 수 있다. 원본 문서마다 그 파일의 마지막 커밋을 따로 보여 준다. 정보가 접혀 있어도 본문·제한·경고는 숨기지 않는다. 좁은 화면의 긴 표는 표 안에서 가로로 이동해 나머지 열을 읽는다.
- 시스템 진행 현황(`/admin/manual/progress`)은 위쪽 「개선 목표·검증 현황」과 아래쪽 기존 구현 현황 표, 두 구역으로 나뉜다. 기능을 고르면 `/admin/manual/progress/[기능ID]` 상세에서 계획 원문과 검사별 현재 상태·이유·결과값·증거·검증 코드 커밋·환경·이력을 본다.
- 화면에서 직접 편집하지 않는다. 문서 변경은 저장소 커밋과 배포로 반영한다. 나중에 화면 편집기를 만들더라도 저장은 git 커밋이어야 한다.
- 일반 사용자와 권한 없는 사용자는 접근할 수 없다. 현재 관리자 역할은 대표 로그인과 같다.

1. 기능·규칙·운영 절차가 실제로 바뀐 경우에만 관련 Markdown을 고친다.
2. `manual/CHANGELOG.md`에 이유와 영향을 짧게 기록한다.
3. 문서의 링크와 실제 기능·화면을 확인한다.
4. 코드와 문서를 같은 변경으로 커밋·배포한다.
5. 배포 후 관리자 화면에서 최신 문서와 배포 버전이 함께 보이는지 확인한다.

### 검증 결과 적는 법

언제 적나.

- 자동 시험을 돌린 직후, 결과가 나온 그때.
- 대표가 화면·기기에서 직접 확인한 직후.

무엇을 적나. 결과 파일 한 줄마다 아래를 채운다. 필드 이름은 실제 JSON 키다.

- `checkId` — 계획서의 검사 ID
- `outcome` — `pass`(통과)·`fail`(실패)·`unverified`(미검증)·`excluded`(제외) 중 하나. 「재검증 필요」는 손으로 적는 값이 아니라 화면이 계산한다
- `value` — 실측값 또는 사유. 비우지 않는다
- `evidence.ref` — 다시 찾아갈 수 있는 시험 파일·문서 경로
- `evidence.checkedAt` — 확인일(시각까지 알면 시각도)
- `evidence.by` — 사람이 확인했으면 확인자. 자동 시험은 생략 가능
- `codeCommit` — 검증한 코드 커밋(결과 파일을 저장한 커밋이 아니다)
- `planVersion` — 그때 계획 버전
- `environment` — 기기·브라우저·뷰포트 또는 「도메인 함수 직접 실행」
- `measured` — 목표가 셀 수 있는 수를 요구할 때 `{covered, total}`. 덜 쟀으면 그대로 적는다

하지 말 것.

- 이전 기록을 지우지 않는다. 새 줄을 덧붙인다.
- 증거 없는 통과를 적지 않는다.
- 대표가 손으로 재야 하는 항목(F07-01·05·06처럼 사람 측정)을 AI가 대신 통과 처리하지 않는다.
- 아직 측정하지 않은 항목을 0으로 채우지 않는다. 미측정으로 남긴다.
- **목표가 요구한 범위를 다 재지 않았으면 통과로 적지 않는다.** 「16/16 시나리오」가 목표인데 하나만 쟀으면 미검증이고, `measured`에 `1/16`을 남긴다. 화면이 이것을 세므로 덜 잰 통과는 초록불이 안 켜진다.

계획 자체를 바꾸면(검사 추가·삭제·목표값 변경) 계획서의 계획 버전을 올리고 바꾼 이유를 남긴다. 옛 결과는 그대로 두고, 새 결과에는 새 계획 버전을 적는다.

- 실제 회사 업종과 조직 구조
- 금액 구간별 승인자 및 승인 단계
