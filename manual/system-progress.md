# 시스템 구성 진행 현황

이 문서는 Coreloom의 기능별 구현 상태를 추적한다. 기능이 추가되거나 상태가 바뀌면 같은 커밋에서 이 표를 갱신한다.

상태 기준:
- **완료**: `main`에 코드가 있고 화면 또는 API로 동작한다.
- **PC 확인 필요**: 코드는 `main`에 있지만 로그인·실데이터 환경에서 아직 확인하지 않았다.
- **진행 중**: 브랜치에서 작업 중이다.
- **미착수**: 범위에 있지만 아직 시작하지 않았다.
- **자격 대기**: 외부 서비스 자격·공급자가 준비되어야 시작할 수 있다.

### 먼저 정할 두 가지

- **입력량 감소 기준:** 개선 전후 동일 결과·동일 경로의 직접 입력 필드 수가 필요합니다. 과거의 보이는 필드 3→2개와 실제 입력 6필드 기록은 서로 다른 측정입니다. 이를 섞어 30% 감소로 판정하지 않습니다. 비교 기준을 확보할 수 없으면 목표 변경을 승인받고 계획 버전을 올립니다.
- **AI 실제 반영 범위:** 현재 AI 대화는 읽기 전용입니다. 업무 변경이 없는 상태를 ‘반영 완료’로 만들거나 대화 이력 저장으로 대신하지 않습니다. 초안·반영 사례의 분류 시험을 모의 사례로 할지, 실제 반영 재조회 항목을 별도 쓰기 기능 계획으로 보류할지 먼저 결정합니다. 통과 수를 늘리려고 쓰기 도구를 추가하지 않습니다.

### 목표와 화면 구성

업무 지도는 ‘일의 순서’, 시스템 구조도는 ‘기능과 자료의 관계’를 설명한다. 비개발자인 대표가 자료의 저장 위치와 AI가 할 수 있는 일을 구분하는 것이 목표다.

중앙에 Coreloom을 두고 아래 다섯 갈래를 연결한다. 한 항목을 누르면 설명 하나만 펼치며, 같은 항목을 다시 누르면 닫는다. 넓은 화면에서는 가로 공간을 활용하고, 좁은 화면에서는 세로로 배치해 선택한 항목 바로 아래에 설명을 둔다. 현재 디자인 토큰과 한글 위계를 유지한다.

| 구성 | 먼저 보여 줄 요점 | 펼쳤을 때 구분할 것 |
| --- | --- | --- |
| 회사 기록 | DB에 저장 | 회사 기록·파일 식별자와 파일 원본은 다름 |
| 원본 파일 | 서버 PC에 비공개 보관 | 문서·대화 첨부 보관과 AI의 원본 읽기 권한은 별개 |
| AI 대화 | 허용 자료만 조회 | 서버 PC 구독 실행기·조회 권한·기록 변경 및 외부 발송 제한 |
| 외부 연결 | 연결마다 조건이 다름 | 로그인, 승인 후 메일 발송, Recho 수동 근거 연결과 미제공 자동 동기화 |
| 운영 문서 | Git 원본을 표시 | 제품 문서와 공용 working-method 원본의 역할 |

선은 관계만 뜻한다. 자동 처리·전체 자료 전송·실시간 정상 연결을 뜻하지 않는다. DB·권한·발송·확정·외부 연동을 새로 구현하지 않는다. 비밀·실데이터·서버 주소는 표시하지 않는다. 내용은 Markdown 정본에서 읽으며 별도 HTML 사본을 운영 정본으로 두지 않는다. 원본이 없거나 잘못되면 명확한 안내를 보여준다.

채팅의 시안 확인은 위 실제 기능 검증을 대신하지 않는다. 완료 표시에는 확인일·코드 커밋·환경·측정값·증거를 함께 남긴다. 실시간 상태 수집 기능을 추가하는 계획은 아니다.

남은 대표 확인: 구조도를 보고 **파일 원본은 어디에 있는지, AI 조회와 발송 권한이 어떻게 다른지, Recho 연결이 수동인지 자동인지** 세 가지를 설명한다(SM-06). 실제 Fold를 닫고 펼쳐 각각 다섯 항목을 터치·스크롤해 본다(SM-09). 이 두 결과는 AI가 대신 통과 처리하지 않는다.

PC 검증 후 브라우저 제어 연결이 끊겨 마지막 재확인과 임시 화면 폭 설정 해제는 확인하지 못했다. 앞서 측정한 결과와 구분하며, 새 세션에서 화면을 다시 열어 확인한다.
