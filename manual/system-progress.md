# 시스템 구성 진행 현황

이 문서는 Coreloom의 기능별 구현 상태를 추적한다. 기능이 추가되거나 상태가 바뀌면 같은 커밋에서 이 표를 갱신한다.

상태 기준:
- **완료**: `main`에 코드가 있고 화면 또는 API로 동작한다.
- **PC 확인 필요**: 코드는 `main`에 있지만 로그인·실데이터 환경에서 아직 확인하지 않았다.
- **진행 중**: 브랜치에서 작업 중이다.
- **미착수**: 범위에 있지만 아직 시작하지 않았다.
- **자격 대기**: 외부 서비스 자격·공급자가 준비되어야 시작할 수 있다.

## 승인·반려 8개 서버 액션 — 차단 자동 시험

`codex/approval-action-tests`에서 실제 서버 액션·저장 처리·도메인 판단을 연결하고 DB 등 외부 입출력만 대역으로 바꾼 검사를 추가했다. 신규 33개(76조건), 전체 76파일 545개 시험과 타입·추가 파일 코드 검사 통과. 미로그인/권한 없음, 잘못된 승인값, 이미 결정된 기록, 없는 기록, 필수 사유·결과·원본 누락의 쓰기 차단과 정상 요청을 대조했다. [AD-15~20 확인 기록](checks/approval-detail-2026-09-06.md)에서 결과와 한계를 본다. 외부 CI·main 반영은 별도이며 제품 코드·실제 DB·서버·실기기는 변경하거나 실행하지 않았다. HTTP 인증·동시성·DB 원자성 검증은 별도다.

### 목표와 화면 구성

업무 지도는 ‘일의 순서’, 시스템 구조도는 ‘기능과 자료의 관계’를 설명한다. 비개발자인 대표가 자료의 저장 위치와 AI가 할 수 있는 일을 구분하는 것이 목표다.

중앙에 Coreloom을 두고 아래 다섯 갈래를 연결한다. 한 항목을 누르면 설명 하나만 펼치며, 같은 항목을 다시 누르면 닫는다. 넓은 화면에서는 가로 공간을 활용하고, 좁은 화면에서는 세로로 배치해 선택한 항목 바로 아래에 설명을 둔다. 현재 디자인 토큰과 한글 위계를 유지한다.

| 구성 | 먼저 보여 줄 요점 | 펼쳤을 때 구분할 것 |
| --- | --- | --- |
| 회사 기록 | DB에 저장 | 회사 기록·파일 식별자와 파일 원본은 다름 |
| 원본 파일 | 서버 PC에 비공개 보관 | 문서·대화 첨부 보관과 AI의 원본 읽기 권한은 별개 |
| AI 대화 | 허용 자료만 조회 | 서버 PC 구독 실행기·조회 권한·기록 변경 및 외부 발송 제한 |
| 외부 연결 | 연결마다 조건이 다름 | 로그인, 승인 후 메일 발송, Recho 수동 근거 연결과 미제공 자동 동기화 |
| 운영 문서 | Git 원본을 표시 | 제품 문서와 공용 working-method 원본의 역할 |

선은 관계만 뜻한다. 자동 처리·전체 자료 전송·실시간 정상 연결을 뜻하지 않는다. DB·권한·발송·확정·외부 연동을 새로 구현하지 않는다. 비밀·실데이터·서버 주소는 표시하지 않는다. 내용은 Markdown 정본에서 읽으며 별도 HTML 사본을 운영 정본으로 두지 않는다. 원본이 없거나 잘못되면 명확한 안내를 보여준다.

## 개선 검증 계획 — 구현 현황과 별도

기능별 목표·28개 검증 항목은 [개선 계획](../docs/superpowers/plans/2026-09-05-measurable-improvements.md)에 있다. 실제 결과는 [결과 파일](../docs/quality/verification-results.json)에서 본다. F07 목표·체크리스트 조회 화면(`/admin/manual/progress`, 상세는 `/admin/manual/progress/[기능ID]`)은 2026-09-05 `main`에 병합됐다(PR #89). 대표 로그인 화면 확인은 아직이다. 사람이 재야 하는 F07-01·05·06은 대표 확인을 기다린다. 3단계(F05·F02)는 PR #92, 4단계(F01·F03)는 PR #93으로 `main`에 들어갔다. F01-01·02·04·F03-03·04 통과 줄은 결과 파일에 있다. F01-03·F03-01·02 사람 측정은 아직이다. 위 구현 상태를 새 검증의 통과로 간주하지 않는다. 다음은 5단계 F04이며 [Claude 인계](handoffs/2026-09-05-claude-stage5-ai-status.md)를 본다. 4단계 인계는 [여기](handoffs/2026-09-05-cursor-stage4-client-quote-approvals.md), 3단계는 [여기](handoffs/2026-09-05-cursor-stage3-accuracy-and-drafts.md), 그날 오전의 [Claude 인계](handoffs/2026-09-05-claude-measurable-improvements.md)는 2단계 착수 전 시점이다.

대표가 직접 재야 하는 시험의 준비물은 `docs/quality/`에 있다 — 승인 판단 5사례 정답표(`approval-review-cases.md`), 탐색 10건·지시문(`approval-search-cases.md`), AI 상태 분류 6사례(`ai-status-classification-cases.md`). 모두 응시자가 시험 전에 보면 안 된다.

🔴 **통과 수를 읽을 때** — 목표가 요구한 범위를 다 재야 통과다. 2026-09-05에 통과 6건이 범위 미달로 정정됐다. 지금은 화면이 그것을 세지만, 목표에 셀 수 있는 수가 없는 검사는 여전히 사람이 값을 읽어야 한다.
